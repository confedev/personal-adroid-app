# Feature Specification: Main Menu and Version Display

## 1. Overview
The **Main Menu** serves as the application's root destination, presenting navigation options to available test features (`Test 1` and `Test 2`) while dynamically displaying the current compile-time application version.

---

## 2. User Stories & Business Requirements

- **User Story:** As an application tester, I want to see a clean menu when opening the app with clear buttons for Test 1 and Test 2, and the compile-time app version displayed prominently, so I know which version of the app I am testing.
- **Business Rules:**
  - The menu must provide direct navigation to:
    - `test1 (get json)` -> Navigates to `Screen.Test1`
    - `test2 (get image)` -> Navigates to `Screen.Test2`
  - Version Display:
    - Displayed clearly on the screen (header or footer).
    - Extracted dynamically from `BuildConfig.VERSION_NAME` generated by the Gradle build system (`app/build.gradle.kts`).
    - Must not be hardcoded in XML or UI files.
  - All textual labels must be sourced from Android string resources (`strings.xml`).

---

## 3. UI Layout & Interaction Flow

```mermaid
graph TD
    A[Launch App] --> B[MenuScreen]
    B -->|Tap 'test1 (get json)'| C[Test1Screen]
    B -->|Tap 'test2 (get image)'| D[Test2Screen]
    B -->|Read BuildConfig.VERSION_NAME| E[Display Version: 'v1.0.0']
    C -->|Tap Back| B
    D -->|Tap Back| B
```

### 3.1 Screen Components
- **Top Bar:** Application name ("Personal Android App").
- **Menu Card / Buttons:**
  - Button 1: "test1 (get json)" navigating to Test 1.
  - Button 2: "test2 (get image)" navigating to Test 2.
- **Version Badge:** Text label formatted as `"Version: <VERSION_NAME>"` displayed in subtle styling at the bottom of the screen.
